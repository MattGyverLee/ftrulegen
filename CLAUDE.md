## Project Overview

**FLExTrans Rule Assistant** is a 64-bit Windows desktop application built with JavaFX 8 and Java that helps users generate FLExTrans transfer rules. The application is an IDE-style tool for creating linguistic transformation rules used with FieldWorks Linguistic Explorer (FLEx).

- **License**: LGPL 2.1 or later
- **Target Platform**: Windows (64-bit only)
- **Version**: Currently at v1.6.0
- **Build System**: Apache Ant with JavaFX ant tasks
- **IDE**: Eclipse (with JavaFX support)

## Building

### Build with Ant

The project uses Apache Ant with JavaFX ant tasks. The main build file is `build/build.xml`.

**Full build (Windows 64-bit native bundle):**
```bash
cd build
ant do-deploy
```

This creates a Windows .exe installer using Inno Setup. The build process:
1. Stages dependencies and source files
2. Compiles Java sources
3. Creates a self-contained JavaFX application
4. Generates a Windows .iss file
5. Builds the installer

**Available Ant targets in build/build.xml:**
- `init-fx-tasks`: Initialize JavaFX ant tasks
- `setup-staging-area`: Copy dependencies and resources to build area
- `do-compile`: Compile Java sources to build/classes
- `do-deploy`: Full build pipeline (default)

**Build from Eclipse:**
Right-click project → Run As → Ant Build (uses build.fxbuild configuration)

### Notes on Build Configuration

- The `.fxbuild` file defines JavaFX application metadata (app name, version, main class)
- Version is configured in both `build.fxbuild` and `build/build.xml` - keep them in sync
- The build uses modularity (org.eclipse.jdt.core.javabuilder)
- Output goes to `build/classes` and `build/dist/` for packaging
- Windows-specific: The buildWindows64bit.xml variant is available for 64-bit builds

## Internationalization (i18n)

The application supports **4 languages**: English (en), German (de), Spanish (es), French (fr).

**Localization files:**
- `src/org/sil/ftrulegen/resources/RuleGen.properties` (fallback/default)
- `src/org/sil/ftrulegen/resources/RuleGen_en.properties`
- `src/org/sil/ftrulegen/resources/RuleGen_de.properties`
- `src/org/sil/ftrulegen/resources/RuleGen_es.properties`
- `src/org/sil/ftrulegen/resources/RuleGen_fr.properties`

**How it works:**
- The `Main` class uses `ObservableResourceFactory` from org.sil.utility library to manage resource bundles
- UI strings are loaded via ResourceBundle; language can be switched at runtime
- When adding UI text, add key-value pairs to ALL `.properties` files to support all languages

**To add a new string:**
```properties
# In all RuleGen_*.properties files:
my.new.key = Translated text here
```

## Architecture Notes

### Layered Architecture

1. **View Layer** (`org.sil.ftrulegen.view`):
   - JavaFX controllers (extend from org.sil.utility base classes)
   - FXML layout files for UI components
   - Handles user input and updates UI
   - Communicates with services for business logic

2. **Model Layer** (`org.sil.ftrulegen.model`):
   - Core domain classes: `FLExTransRule`, `Phrase`, `Word`, `Category`, `Feature`, `Affix`
   - Represents the rule structure user is editing
   - Uses JAXB annotations for XML binding
   - `FLExTransRuleGenerator`: Orchestrates rule creation and generation

3. **Service Layer** (`org.sil.ftrulegen.service`):
   - **XML Persistence**: `XmlBackEndProvider` (rules), `XMLFLExDataBackEndProvider` (FLEx data)
   - **Validation**: `ValidityChecker` - checks rule correctness before generation
   - **Analysis**: `ConstituentFinder` (finds linguistic components), `RuleIdentifierAndParentSetter` (sets rule relationships)
   - **Output**: `WebPageProducer` (generates HTML), `WebPageInteractor` (exports/displays results)

4. **FLEx Integration** (`org.sil.ftrulegen.flexmodel`):
   - `FLExData`: Wrapper around FLEx database content
   - `FLExCategory`, `FLExFeature`, `FLExFeatureValue`: Domain data from FLEx
   - `SourceFLExData`, `TargetFLExData`: Language pair specific FLEx data
   - Loads from XML exports of FLEx database

### Key Design Patterns

- **Model-View-Controller (MVC)**: Controllers in `view` package manage UI, models hold data
- **Service Layer**: Business logic separated from UI and persistence
- **JAXB for XML**: Models use `@XmlRootElement`, `@XmlElement` for automatic serialization
- **Resource Bundles**: Locale-based string management via `ResourceBundle`
- **JavaFX Bindings**: Controllers use JavaFX observables for reactive UI updates

### Important Classes to Know

- **Main**: Entry point, handles initialization, language selection, application lifecycle
- **FLExTransRuleGenerator**: Core generator class, orchestrates rule creation
- **FLExTransRule**: A single transfer rule with source pattern and target replacement
- **Phrase**: Represents source or target pattern (contains Words)
- **Word**: Individual constituent in a phrase
- **Feature**: Linguistic feature with values (e.g., gender=masculine)
- **Category**: Grammatical category (e.g., noun, verb)
- **XmlBackEndProvider**: Handles saving/loading rules from XML files
- **XMLFLExDataBackEndProvider**: Loads linguistic data from FLEx XML exports

## Code Style and Conventions

- **Package naming**: `org.sil.ftrulegen.*` (SIL namespace convention)
- **File encoding**: UTF-8 (configured in `.settings/org.eclipse.core.resources.prefs`)
- **Class naming**: PascalCase, Controllers end with `Controller`, Tests end with `Test` or `Tests`
- **Constants**: Uppercase with underscores, in `Constants.java` or class-specific
- **JAXB enums**: Use `@XmlEnum` for extensible rule elements (e.g., `HeadValue`, `AffixType`)
- **Exception handling**: Uses custom `HandleExceptionMessage` utility from org.sil.utility
- **JavaFX**: Controllers use FXML, initialize UI elements in `initialize()` method

## Common Development Tasks

### Adding a New Language

1. Create new properties file: `src/org/sil/ftrulegen/resources/RuleGen_XX.properties` (XX = language code)
2. Copy all key-value pairs from RuleGen_en.properties
3. Translate all values
4. Update `Main.java` RESOURCE_FACTORY initialization if needed for language selection

### Adding a New Rule Property

1. Create model class or add field to existing model in `org.sil.ftrulegen.model`
2. Add JAXB annotations (`@XmlElement`, `@XmlAttribute`) for XML serialization
3. Update service classes that handle the property (ValidityChecker, WebPageProducer, etc.)
4. Update UI controllers in `view` package to show/edit the property
5. Add test cases to verify serialization and generation

### Modifying XML Structure

1. Edit the DTD: `FLExTransRuleGenerator.dtd`
2. Update model classes with JAXB annotations
3. Update `XmlBackEndProvider` if custom serialization needed
4. Update test data in `test/org/sil/ftrulegen/testdata/`
5. Run XML persistence tests to verify round-trip works

### Debugging

- **In Eclipse**: Use the Eclipse debugger; set breakpoints in Java files
- **JavaFX-specific**: Look at application window resizing, CSS loading in `src/org/sil/ftrulegen/application.css`
- **XML issues**: Check the generated XML against `FLExTransRuleGenerator.dtd`
- **Locale issues**: Test with different `Locale` objects in Main

## Known Dependencies and Interactions

- **LibJavaDev** (SIL custom library): Provides UI utilities (`ControllerUtilities`, `HandleExceptionMessage`, `ObservableResourceFactory`)
